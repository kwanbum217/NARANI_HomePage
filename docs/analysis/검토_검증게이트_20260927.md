## 2. 차단 판정

차단 0건입니다.

| 번호 | 항목 | 판정 근거 |
| --- | --- | --- |
| 1 | 인터랙션 체크의 실패 보고 | `scripts/audit/checks/nav.js`, `form.js`, `dialog.js` 가 위반 사유를 모아 `rep.fail` 에 담고, 기대와 같으면 `null` 을 둡니다. 기대 조건은 정본 3장의 인터랙션 절과 일치합니다 |
| 2 | `interact.swift` 종료 코드 | 결과 없음, 비 JSON, `fail` 비 null 을 실패로 보고 `exit(1)` 하며, 전부 통과하면 `exit(0)` 입니다. `scripts/verify.sh` 6/6 단계는 `set -e` 하에서 이 종료 코드를 그대로 받으므로 게이트가 동작합니다 |
| 3 | `a11y.swift` 신규 판정 | 작은 터치 타겟, `h1` 개수, `lang` 값, 이미지 `alt` 누락, 결과 없음에서 `issues` 를 올리고, 0건이 아니면 `exit(1)` 합니다 |
| 4 | 기존 접근성 판정 유지 | 오버플로우와 라벨 누락의 수집 로직과 집계 방식이 그대로이며, 정상 출력 형식도 유지됩니다 |
| 5 | 폼 성공 패널 기대 유지 | 성공 표시 기대가 체크에 남아 있고, `src/` 이하 변경이 없습니다 |
| 6 | 이메일·개인정보 문구 유지 | 작업 분 diff 에 이메일과 개인정보 문구 변경이 없으며, `src/` 변경도 없습니다 |
| 7 | 정본 6장 실패 조건 추가 | 접근성 실패 조건 한 줄이 추가되었고, 기존 절의 수치는 수정되지 않았습니다. 바뀐 것은 인용 블록의 수정일과 추가된 Chrome 실측 절, 승격 기록 한 줄뿐입니다 |

## 3. 권고

권고 2건입니다.

| 번호 | 내용 | 이유 |
| --- | --- | --- |
| 1 | 카피 변경 시 체크 스크립트 동반 갱신 | 기대 문구가 체크 스크립트에 고정되어 있어, 안내 문구나 요금 표시가 바뀌면 체크도 함께 고쳐야 합니다 |

## 4. 검증 내역

- 검증한 것: 대상 파일 5건과 정본 6장의 `git diff` 대조, `scripts/verify.sh` 의 종료 코드 배선 확인, `src/` 와 이메일·개인정보 문구의 변경 없음 확인.
- 검증하지 못한 것: `npm run verify` 실행과 브라우저 렌더 확인은 제약에 따라 실행하지 않았으므로 미검증으로 남깁니다.
