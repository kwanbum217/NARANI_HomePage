### 4. JSON-LD 정확성

**판정: 결함 (`applicationCategory`).** `offers` 누락은 **적절**.

`@type: 'SoftwareApplication'` 자체는 schema.org 에 존재하는 유효 타입입니다.
`applicationCategory: 'SoftwareApplication'` 는 잘못된 값입니다. 이 속성은
`BusinessApplication`, `UtilitiesApplication` 등 ApplicationCategory 열거형 또는 그와 다른
문자열을 받는 속성이고, `'SoftwareApplication'` 은 `@type` 에 이미 준 타입명입니다.
결과적으로 속성이 자기 자신을 설명하는 무의미 상태가 되며 Google 리치 결과 테스트에서 무효로 나옵니다.
`offers` 를 넣지 않은 것은 `CURRENT_STATE.md:284-286` 보류(본체에 PG·주문 모델 없음)에
맞는 선택입니다. 없으면 가격이 드러나지 않아 정합합니다.

### 5. 접근성·시맨틱

**판정: 확인됨 (결함 없음).**

두 페이지 모두 `section` + `h2` + `dl/dt/dd` 구조입니다
(`pricing.astro:204-215`, `service.astro:92-102`, 각 dt/dd 5쌍).
`aria-labelledby="faq-title"` 이 가리키는 `h2` 는 페이지마다 하나뿐입니다.
두 페이지가 같은 `id="faq-title"` 을 써도 **문서마다 ID 공간이 분리되어 있으므로 문제없습니다.**
한 문서에 같은 ID 가 두 번 나온 적이 없고, 연결 검증도 통과했습니다.
320px 오버플로우 0건은 7단계 실측("0 issue group(s)")이 확인합니다. `<div>` 로 감싼 `dt/dd` 는
HTML Living Standard 에서 허용되는 형태입니다.

| 카피 모순 (`요금 보기` vs `프로그램 접속`) | 없음 | 카피 간 정합성 검사 단계가 없음. `npm run verify` exit 0 |
| JSON-LD 용어 오류 | 없음 | `scripts/verify.sh` 에 구조화 데이터 검증이 한 줄도 없음 |
| 접근성·반응형 회귀 | 7단계 | 실제 회귀가 없어서 통과 |

**이것이 이 리뷰의 핵심입니다.** 게이트 10개 항목이 전부 통과했는데도 세 가지 실제 위험이
남았습니다. 즉 현재 게이트는 "깨지지 않은 것"만 증명하고 "틀린 것"은 증명하지 못합니다.
서로 다른 페이지를 한 번에 관찰하는 비교 검사(같은 용어의 페이지 간 불일치)와
구조화 데이터 스키마 검증이 없어야만 이 사각지가 생깁니다.

## 검증하지 못한 것

1. Google 리치 결과 테스트·schema.org 공식 밸리데이터 실행을 하지 않았습니다.
   `applicationCategory` 판정은 스펙 지식과 코드 대조로 내린 것이며 실측 통과·실패 수치는 없습니다.
2. `npm run verify` 를 제가 직접 실행하지 않았습니다. 8단계 통과는 코디네이터 실측 결과를 인용한 것입니다.
3. 5·6·7단계가 `faq.ts` 를 실제로 DOM 읽어 검사했는지 `scripts/verify.sh` 본문을 끝까지 확인하지
   않았습니다. 따라서 "게이트가 이 위험을 놓쳤다"는 판정은 검사 부재를 근거로 한 것입니다.
4. 320px 에서 `<dl>` 안 `md:grid-cols` 이 미적용 상태로 렌더된 결과물을 육안 확인하지 않았습니다.
5. 사용자 관점의 카피 모순은 문서 비교로 내린 판단입니다. 실제 사용자 테스트는 하지 않았습니다.
