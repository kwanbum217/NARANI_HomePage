## 2. 변경

기대값을 `scripts/audit/expected.mjs` 가 정본에서 파생하고, `scripts/audit/interact.swift`
가 `EXPECT_JS` 환경변수로 그 산출물을 받아 체크 스크립트 앞에 주입합니다. 체크
스크립트는 비교 대상을 `window.__expected` 에서 읽습니다.

| 기대값 | 파생 출처 |
| --- | --- |
| 다이얼로그 제목 | `src/data/pricing.ts` `plans` 의 `label` + `src/pages/bidbox/pricing.astro` 의 제목 템플릿 |
| 다이얼로그 금액 | `src/data/pricing.ts` `plans` 의 `price` + `src/pages/bidbox/pricing.astro` 의 통화 표기 규칙 |
| 폼 첫 오류 문구 | `src/scripts/app.js` 의 `nameError` 기본값 |
| 전송 중 라벨 | `src/pages/bidbox/contact.astro` |
| 접수 완료 표시 | `src/pages/bidbox/contact.astro` |

배선:

| 지점 | 동작 |
| --- | --- |
| `scripts/verify.sh` 6단계 | `node scripts/audit/expected.mjs > "$OUT/expected.js"` 로 파생 후 `EXPECT_JS` 로 `interact.swift` 에 전달 |
| `scripts/audit/expected.mjs` | 정본에서 값을 찾지 못하면 오류를 출력하고 종료 코드 1 |
| `scripts/audit/interact.swift` | `EXPECT_JS` 경로를 읽지 못하면 종료 코드 1. 체크 로딩과 같은 방식으로 파일을 읽어 앞에 붙임 |
| `scripts/audit/checks/form.js`, `dialog.js` | `window.__expected` 가 없으면 `fail` 을 채워 실패 처리 |

`src/data/pricing.ts` 는 Node 의 타입 스트리핑으로 직접 import 합니다. 새 npm 패키지를
추가하지 않으며, 저장소 정본 환경(Node v26.10.0)에서 동작합니다.

## 3. 음성 검증

방법: `dist/` 사본을 저장소 밖 `/tmp` 로 복사하고 임시 서버로 서빙했습니다. 기대값은
저장소 `src` 에서 파생한 것을 그대로 썼으므로, 사본만 변형하면 게이트가 불일치를
잡아야 합니다. 변형마다 주입 사실을 확인한 뒤 검사를 실행했습니다.

측정 조건: `scripts/audit/interact.swift` 직접 호출, 경로별 1회, 표본 경로당 1건.
변형용 사본과 임시 서버는 저장소 밖에 두고 정리했습니다.

| 회차 | 변형 | 대상 | 종료 코드 | 게이트가 낸 사유 |
| --- | --- | --- | ---: | --- |
| 기준선 | 없음 | - | 0 | `fail: null` |
| 1 | `450000` -> `451000` | 사본 `bidbox/pricing/index.html` 내장 plans JSON | **1** | `fail: "다이얼로그 금액이 다릅니다 (₩451,000)."` |
| 2 | `성함을 입력해 주세요.` -> `성명을 확인해 주세요.` | 사본 `_astro/*.js` 클라이언트 번들 | **1** | `fail: "첫 오류 문구가 다릅니다 (성명을 확인해 주세요.)."` |

두 변형 모두 종료 코드 1 과 한국어 사유 문구를 냈고, 기준선은 통과했습니다. 정본에서
파생한 기대값이 사본의 카피 변경을 그대로 잡아낸다는 뜻입니다.
