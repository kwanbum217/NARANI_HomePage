### 질문 2. 파생이 조용히 틀어질 수 있는 경로가 있는가

조용히 통과할 수 있는 경로는 한 가지, 크게 깨지는 경로는 전부 명확한 실패로 이어집니다.

조용한 통과 경로: 요금 순서 가정입니다. `scripts/audit/expected.mjs:44` 의 `DIALOG_PLAN_INDEX = 1` 과 `scripts/audit/checks/dialog.js:17` 의 `btns[E.planIndex].click()` 은 같은 인덱스를 공유하고, `src/pages/bidbox/pricing.astro:59` 는 `plans.map` 으로 같은 순서로 렌더합니다. 따라서 `plans` 순서가 바뀌면 기대값과 클릭 대상이 함께 움직여 게이트가 조용히 통과합니다. 변경 전에는 버튼 인덱스 1과 리터럴 `500포인트 구매`·`₩450,000` 이 고정되어 있어 순서 변경이 명확한 실패로 드러났으므로, 이 한 차원에서는 게이트 강도가 낮아졌습니다. 다만 순서는 정본 데이터 자체의 결정이라 게이트가 막을 대상이 아니며, 구 게이트의 순서 고정은 의도된 검사가 아니라 하드코딩의 부수효과였습니다. 판정은 차단이 아니라 권고 2번입니다.

크게 깨지는 경로는 모두 명확한 실패입니다. 다섯 정규식(`scripts/audit/expected.mjs:50-80`)이 따옴표 style, 표현식 형태, 마크업 순서에 예민한 것은 사실입니다. 그러나 매칭 실패 시 `pick` (`scripts/audit/expected.mjs:35-41`)이 예외를 던지고, 통화 규칙 누락 (`scripts/audit/expected.mjs:75-80`)과 플랜 부재 (`scripts/audit/expected.mjs:82-85`)도 예외를 던지므로, 파생 틀어짐은 `verify.sh` 의 `set -e` (`scripts/verify.sh:9`)에 걸려 종료 코드 1 로 멈춥니다. 조용히 틀린 기대값을 주입하는 경로는 없습니다. `pricing.astro` 안에 통화 표기가 두 곳(`src/pages/bidbox/pricing.astro:5` 의 `won` 정의와 `src/pages/bidbox/pricing.astro:147` 의 다이얼로그 하드코딩)에 있는 점은 기존 구조이며, 두 곳이 어긋나면 파생(5행 기준)과 렌더(147행 기준)가 달라져 게이트가 명확히 실패하므로 검출됩니다. 이는 권고 5번으로만 남깁니다.

### 질문 4. 판정식 의미 변화(정규식에서 문자열 포함으로)가 허용되는가

허용됩니다. 약한화가 아니라 실질 동등이며, 리터럴 길이 기준으로는 오히려 엄격해졌습니다. 변경 전 `scripts/audit/checks/form.js` 의 `/접수되었습니다/.test(h.textContent)` 와 변경 후 `h.textContent.includes(E.successText)` (`scripts/audit/checks/form.js:34`)는 모두 부분 문자열 검사이며, 파생된 `E.successText` 는 `문의가 접수되었습니다` (`src/pages/bidbox/contact.astro:46`)로 기존 정규식보다 긴 리터럴을 요구합니다.

별도로 확인된 기존 약점은 이 커밋이 만든 것이 아니므로 차단 사유가 아닙니다. 접수 완료 `h2` (`src/pages/bidbox/contact.astro:46`)와 폼 제목 `h2` (`src/pages/bidbox/contact.astro:55`)는 모두 `x-show` 로 표시만 바뀌고 DOM 에 항상 존재하므로, 존재 여부 검사는 제출 전에도 참입니다. 변경 전후 동일하게 존재 여부만 보며 가시성을 단언하지 않습니다. 권고 3번으로 남깁니다.

### 질문 5. 실행 환경 전제 (`.ts` 직접 import)

정본 환경에서 동작하는 이유가 규명됩니다. `scripts/audit/expected.mjs:21` 은 `../../src/data/pricing.ts` 를 확장자 명시 형태로 import 하며, Node 공식 문서에 따르면 타입 스트리핑은 v22.18.0·v23.6.0 부터 기본 활성화되었고 v25.2.0·v24.12.0 부터 안정 상태입니다. 이 워크트리의 `node --version` 실측값은 v26.10.0 이므로 기본 활성화 범위 안에 듭니다. `src/data/pricing.ts:8-19` 는 `type` 선언과 `const` 만 쓰고 `enum`·네임스페이스 등 변환이 필요한 문법을 쓰지 않으므로 스트리핑 대상(erasable syntax only)에 해당합니다.

CI 의 다른 Node 버전에서 깨질 가능성은 없습니다. CI(`.github/workflows/ci.yml`)는 Node `22` 를 쓰지만 빌드와 링크 무결성만 실행하고 `expected.mjs` 를 실행하지 않으므로, `.ts` import 경로를 밟지 않습니다. `verify.sh` 는 macOS WebKit 전제라 로컬 실행용입니다. 남은 위험은 정본 환경이 아닌 구형 Node(v22.18 미만) 셸에서 `verify.sh` 를 돌릴 때 6단계에서 import 오류로 멈추는 경우이며, 그 경우에도 조용히 통과가 아니라 종료 코드 1 로 멈춥니다. 판정은 차단이 아니라 권고 4번입니다.
