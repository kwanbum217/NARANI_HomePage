### 질문 1. 가시성 단언이 추가되었는가 (권고 3번)

추가되었습니다. 기존 검사는 `main h2` 의 존재 여부만 보아 제출 전에도 참이었으나, 변경분은 렌더된 사각형 기준으로 판정합니다.

| 확인 항목 | 결과 | 근거 |
| --- | --- | --- |
| 성공 제목 탐색 | 유지 | `scripts/audit/checks/form.js:19-20` 의 `successHeading()` 은 `E.successText` 를 포함한 `main h2` 를 찾습니다 |

| 두 상태 구분 | 구분됩니다 | 성공 패널(`src/pages/bidbox/contact.astro:42`)과 폼(`src/pages/bidbox/contact.astro:54`)은 `x-show` 로 표시만 바뀌며, `x-show` 는 `display:none` 을 씁니다. `display:none` 조상 아래 요소는 사각형이 0이고 `getClientRects` 가 비므로 숨김은 거짓, 렌더된 제목은 참이 됩니다 |

### 질문 2. 시간 순서가 검증되는가

검증됩니다. 최종 상태만 보는 형태가 아니라 제출 직후와 전송 완료 후를 각각 단언으로 고정했습니다.

| 시점 | 단언 | 근거 |
| --- | --- | --- |
| 전송 중 (클릭 후 약 200ms) | 숨김임 (`successVisibleWhileBusy === false`) | `scripts/audit/checks/form.js:43` 에서 기록하고 `scripts/audit/checks/form.js:54` 에서 검사합니다 |
| 전송 완료 후 (추가 1800ms 대기) | 표시됨 (`successVisible === true`) | `scripts/audit/checks/form.js:45` 에서 기록하고 `scripts/audit/checks/form.js:55` 에서 검사합니다 |

`src/scripts/app.js:70` 의 지연 시뮬레이션 동안에는 상태가 `submitting` 이므로, 첫 표본은 숨김 구간 안에 들고 두 번째 표본은 `sent` 전환 이후에 듭니다. 순서가 뒤바뀌거나 한 시점만 보도록 작성되어 있지 않습니다.

### 질문 3. 새 거짓 음성을 만들지 않았는가

코드 대조상 새 거짓 음성 경로는 확인되지 않았습니다.

| 검토 지점 | 판단 |
| --- | --- |
| 타이밍 여유 | 대기값(200ms·1800ms)은 변경 전과 동일하며, 전송 중 읽기는 기존 `busy` 라벨·`aria-busy` 읽기와 같은 시점입니다. 해당 시점에 `submitting` 이 아니면 기존 단언(`scripts/audit/checks/form.js:52-53`)이 먼저 실패하므로, 새 단언이 추가 타이밍 위험을 만들지 않습니다 |
| 조용한 통과 | Alpine 미동작 등 고장 시 전송 중 단언은 vacuously 통과할 수 있으나 최종 단언(`scripts/audit/checks/form.js:55`)이 실패하므로 전체는 실패합니다. 조용히 통과하는 경로는 없습니다 |
| 판정식 배선 | 실패는 `fail` 에 합쳐져(`scripts/audit/checks/form.js:56`) 기존 판정식(`scripts/audit/interact.swift:30-36`)에 그대로 걸립니다. `interact.swift` 는 수정되지 않았습니다 |

다만 런타임 실행을 하지 않았으므로 실제 통과 여부는 미검증으로 남깁니다 (5장).
