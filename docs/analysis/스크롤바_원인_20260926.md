# /bidbox/service/ scrollWidth 원인 확인

> **작성일**: 2026-09-26
> **상태**: 완료
> **측정 조건**: 대상은 커밋 `da1a34c` 를 `npm run build` 한 `dist/` 의 복사본 8페이지입니다(복사본 폴더에 빌드 커밋을 기록한 `BUILD_HEAD.txt` 를 함께 두었습니다). Google Chrome 154.0.8037.58 을 `--headless=new` 로 띄워 CDP(Node 내장 fetch 와 WebSocket, 디버깅 포트 9902)로 측정했고 `python3 -m http.server` 8902 로 서빙했습니다. 뷰포트 폭은 1440, 높이는 `scripts/verify.sh` 의 PAGES 정의를 따랐습니다(`/company/`, `/bidbox/`, `/bidbox/service/` 는 1900, 나머지 5페이지는 1700). 페이지 load 뒤 1500ms 를 기다린 뒤 값을 읽었고, 처음부터 다시 실행해 2회 측정했습니다.

## 질문

[`브라우저_렌더_비교_20260925.md`](브라우저_렌더_비교_20260925.md) 에서 Chrome 1440 폭 `/bidbox/service/` 의 `documentElement.scrollWidth` 가 1425 로 나왔습니다. 원인이 세로 스크롤바인가?

---

## 방법

8페이지를 각각 열어 페이지별로 `window.innerWidth`, `documentElement.clientWidth`, `documentElement.scrollWidth`, `body.scrollWidth`, `documentElement.scrollHeight`, `window.innerHeight` 를 읽고, 세로 스크롤바 폭을 `innerWidth - clientWidth` 로 계산했습니다. 측정 스크립트와 원시값은 저장소 밖 세션 임시 폴더에 두었고, 세션이 끝나면 남지 않습니다.

## 해석

- 세로 스크롤이 있는 페이지는 `/bidbox/service/` 뿐입니다. `scrollHeight 2104` 가 `innerHeight 1900` 보다 커서 세로 스크롤바가 생겼고, 그 폭 15px 만큼 `clientWidth` 가 1440 에서 1425 로 줄었습니다.
- `/bidbox/service/` 의 `scrollWidth 1425` 는 `clientWidth 1425` 와 같습니다. 콘텐츠가 클라이언트 영역을 넘지 않으므로 가로 넘침이 아닙니다. 2026-09-25 문서의 해석과 같습니다.
- 나머지 7페이지는 세로 스크롤이 없어 스크롤바 폭이 0 이고 `scrollWidth` 도 1440 입니다. 세로 스크롤이 있는 페이지에서만 `scrollWidth` 가 `innerWidth - 15` 로 줄어듭니다.
- 결론: 1425 는 결함이 아니라 세로 스크롤바가 차지한 15px 때문입니다. 뷰포트 높이보다 긴 페이지를 측정할 때 이 차이를 측정 조건으로 기록해야 합니다.
