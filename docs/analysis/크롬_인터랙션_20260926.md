# Chrome 인터랙션 3종 측정

> **작성일**: 2026-09-26
> **상태**: 완료
> **측정 조건**: 대상은 커밋 `da1a34c` 를 `npm run build` 한 `dist/` 의 복사본입니다(복사본 폴더에 빌드 커밋을 기록한 `BUILD_HEAD.txt` 를 함께 두었습니다). Google Chrome 154.0.8037.58 을 `--headless=new` 로 띄워 CDP(Node 내장 fetch 와 WebSocket, 디버깅 포트 9901)로 구동하고 `python3 -m http.server` 8901 로 서빙해 측정했습니다. 시나리오와 선택자는 `scripts/audit/checks/` 의 세 파일을 그대로 따랐고, 시나리오마다 페이지를 새로 열어 2회 실행했습니다.

## 질문

메뉴 토글, 폼 검증, 요금 다이얼로그는 `npm run verify` 에서 WebKit 로만 확인되었습니다. Chrome 에서도 같은 상태가 나오는가?

## 해석

- 세 시나리오의 모든 항목이 [`../context/CURRENT_STATE.md`](../context/CURRENT_STATE.md) 3장 인터랙션 표의 WebKit 결과와 불일치 없이 일치합니다. WebKit 표의 값은 이 문서에 옮겨 적지 않습니다.
- 체크 스크립트가 기록하지만 WebKit 기준표에 없는 값(평시 비활성 여부, 오류 제출 뒤 재제출 가능, 플랜 버튼 개수, 초기 열림 여부)도 두 실행에서 같았습니다.
- 인터랙션 3종은 Chrome(Blink) 과 WebKit 양쪽에서 동일하게 동작합니다. 메뉴 토글, 폼 검증, 요금 다이얼로그의 체크 항목은 이 측정(헤드리스 Chrome, JS `click()`)과 WebKit 검증에서 같았습니다. 명도 대비, CTA 치수, Firefox, 일반 창은 한계 절의 범위입니다.
