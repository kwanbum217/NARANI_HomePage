## 질문

WebKit 기준선(`../context/CURRENT_STATE.md` 3장)의 body 배경·텍스트 대비값이
Google Chrome 에서도 같게 나오는가. 두 번의 실행에서 재현되는가.

## 방법

1. 빌드 커밋 `ee2790e` 산출물을 `/tmp/narani-chrome-contrast-20260927/dist` 로
   복사하고 `python3 -m http.server 8911` 로 서빙했다.
2. `Google Chrome 154.0.8037.58` 을 `--headless=new --remote-debugging-port=9911`
   로 띄웠다. CDP 는 Node 내장 fetch 와 WebSocket 만 썼고, 패키지를 설치하지 않았다.
3. 뷰포트는 `Emulation.setDeviceMetricsOverride` 로 설정하고, `Page.navigate` 로
   이동한 뒤 `Page.loadEventFired` 에서 1500ms 를 기다렸다.
4. `scripts/audit/render.swift` 의 probe 와 같은 방식으로 `document.body` 의
   `backgroundColor`, `color` 를 읽고 상대 휘도 대비를 계산했다. sRGB 채널을
   0-1 로 나눈 뒤 0.03928 이하면 `x/12.92`, 아니면 `((x+0.055)/1.055)^2.4` 로
   선형화하고, 휘도는 `0.2126R + 0.7152G + 0.0722B`, 대비는
   (큰 휘도 + 0.05) / (작은 휘도 + 0.05) 를 소수 둘째 자리에서 반올림했다.
5. 콘솔 오류와 경고 건수는 CDP `Runtime.consoleAPICalled`,
   `Runtime.exceptionThrown`, `Log.entryAdded` 이벤트로 페이지마다 센다.
6. 같은 스크립트를 두 번 실행해 원시 JSON 을 run1.json 과 run2.json 에 따로
   남겼다. 두 실행 결과는 완전히 같았다. 측정 후 Chrome 과 http.server 를
   종료했다. 스크립트와 JSON 은 저장소에 넣지 않았다.

## 해석

- WebKit 기준선은 [`../context/CURRENT_STATE.md`](../context/CURRENT_STATE.md)
  3장의 표를 참고한다. 이번에 잰 Chrome 값은 그 표와 일치한다. 라이트 페이지군
  (`/`, `/company/`, `/404.html`) 의 배경 `rgb(250, 249, 247)`, 텍스트
  `rgb(10, 31, 51)`, 대비 15.88, 다크 페이지군(BIDBOX 5종)의 배경
  `rgb(0, 0, 0)`, 텍스트 `rgb(242, 247, 250)`, 대비 19.46 이 각각 같다.
- 콘솔 오류와 경고는 8개 페이지 2회 실행 전부 0건으로, WebKit 기준선의 JS 오류
  0건과도 일치한다.
- 두 레지스터의 대비값은 본문 텍스트 기준 4.5:1 요건을 넘는다.

## 한계

- 이 값은 `--headless=new` 모드 Chrome 154 에서 얻은 것이므로 일반 창 Chrome,
  다른 버전, 다른 OS 의 렌더가 같다고 단정할 수 없다.
- 측정은 body 의 computed 스타일 배경과 텍스트만 본다. 개별 컴포넌트나 섹션,
  이미지 위 텍스트의 대비는 이 측정 범위가 아니다.
- 측정 대상은 빌드 커밋 `ee2790e` 의 복사본이므로 이후 커밋의 dist 는 다른 값을
  가질 수 있다. 원시 JSON(run1.json, run2.json)과 스크립트는 저장소 밖
  `/tmp/narani-chrome-contrast-20260927/` 에만 남았다.
- `Page.loadEventFired` 뒤 1500ms 를 기다렸으나 폰트 로딩 같은 비동기 리소스가
  대비에 영향을 주는 페이지에서는 더 긴 대기가 다른 값을 줄 수 있다.
