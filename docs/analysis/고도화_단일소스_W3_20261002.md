| 근거 | 위치 | 표기 |
| --- | --- | --- |
| 요금 본문 | `pricing.astro:79` | `공고 · 낙찰` (공백 있음) |
| 다이얼로그 사용 범위 | `pricing.astro:176` | `공고 · 낙찰` (공백 있음) |
| 회사소개 | `company/index.astro:85` 코디네이터 실측 | `공고 · 낙찰` (공백 있음) |
| (참고, 미정본) | `pricing.astro:55` meta description | `공고·낙찰` (공백 없음) |

페이지 본문 3곳이 공백 있는 쪽으로 일관하므로 공백 있는 쪽을 정본으로 삼았고, `faq.ts` 가 이제 공백 있는 쪽을 렌더합니다.
`pricing.astro:55` 의 meta description 은 W4 소유 문장이라 손대지 않았습니다.

## 자가 검증 실행 결과

- **1단계(변경 전)**: `npm run check` exit 0, `npm run build` exit 0,
  `dist/bidbox/service/index.html` 에 `공고 · 낙찰 탐색 및 AI 예측당 1포인트가
  사용됩니다.` 와 `네. 포인트는 조회당 사용됩니다. 동일한 공고를 재조회하면
  포인트가 차감됩니다.` 렌더 확인.
- **2단계(임시 변경)**: `POINT_NOTE` → `임시 검증용 문장입니다. 상수 전파
  테스트로 빌드됩니다.`, `POINT_USAGE_RULE` → `임시 검증용 사용 범위 문장입니다.`
  로 바꾸고 재빌드(exit 0). 결과: `dist/bidbox/service/index.html` 의 FAQ 2번은
  `임시 검증용 사용 범위 문장입니다.`, 3번은 `네. 임시 검증용 문장입니다. 상수
  전파 테스트로 빌드됩니다.` 로 **함께 바뀌는 것을 확인**했습니다. 단,
  `dist/bidbox/pricing/index.html` 의 하드코딩 문장은 원래대로 남아(예상대로)
  W4 병합 후 배선 범위의 책임임을 재확인했습니다.
- **3단계(복원)**: 두 상수를 정본 값으로 되돌리고 재빌드. `grep -c
  '네\. 포인트는 조회당 사용됩니다\.' dist/bidbox/service/index.html` = 1 로
  원값 복귀 확인. `git status --short` 는 `M src/data/faq.ts`,
  `M src/data/pricing.ts`, 기존의 `?? node_modules` 가 전부이며 임시 변경 잔존 없음.

`grep -n "import" src/data/faq.ts` → 1행에 `import { POINT_NOTE, POINT_USAGE_RULE } from './pricing';` 있습니다.
`POINT_NOTE|POINT_USAGE_RULE` 출현 3회(1행 import + 15·19행 사용).

새 한국어 글자를 추가하지 않았습니다. 공백 있는 가운뎃점 표기의 차이는 공백뿐이고,

수정하지 않았으므로 6단계(폰트 서브셋)는 멈출 이유가 없습니다.

## 검증하지 못한 것

1. `npm run verify` 전체(8단계)는 실행하지 않았습니다. 지시받은
   `npm run check`·`npm run build` 와 dist 문장 대조만 했습니다.
2. WebKit 렌더·인터랙션 5~8단계(macOS 전용 검사)는 재연하지 않았습니다.
   데이터 모듈 변경이라 렌더 영향은 FAQ 문장 대조로 대신했습니다.
3. W4 가 `pricing.astro` 를 고치는 중이라 병합 시 그 파일의 문장이
   `POINT_USAGE_RULE` 로 배선되는지는 이 워커가 확인하지 못합니다.
   병합 후 코디네이터의 배선 확인이 필요합니다.
