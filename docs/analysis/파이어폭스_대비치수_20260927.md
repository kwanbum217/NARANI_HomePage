## 질문

WebKit 기준선([`../context/CURRENT_STATE.md`](../context/CURRENT_STATE.md) 3장)의 본문 배경 및 텍스트 대비값과 컴포넌트 실측 치수가 헤드리스 Mozilla Firefox 에서도 동일하게 나오는가. 두 번의 실행에서 오차 없이 재현되는가.

---

## 방법

1. 저장소 `dist/` 산출물을 `/tmp/narani-firefox-metrics-20260927/dist` 로 복사하고, 빌드 커밋 해시(`ee2790e9a0adc4d1d5828e8b1c56b68e6852d92d`)를 `BUILD_HEAD.txt` 에 기록한 뒤 `python3 -m http.server 8921` 로 서빙했습니다.
2. Mozilla Firefox 156.0.1 (바이너리 경로 `/Applications/Firefox.app/Contents/MacOS/firefox`)을 `--headless --remote-debugging-port 9921 --profile /tmp/narani-firefox-metrics-20260927/profile` 로 실행했습니다. 원격 제어는 Firefox Remote Agent 가 제공하는 WebDriver BiDi 프로토콜(`ws://127.0.0.1:9921/session`)을 통해 수행했으며, Node 내장 `fetch` 와 `WebSocket` 만 사용했습니다(추가 npm 패키지 설치 없음).
3. 검증 대상 페이지와 뷰포트는 `scripts/verify.sh` 의 `PAGES` 정의와 동일하게 설정했습니다.
   - `/`: 1440x1700
   - `/company/`: 1440x1900
   - `/bidbox/`: 1440x1900
   - `/bidbox/service/`: 1440x1900
   - `/bidbox/pricing/`: 1440x1700
   - `/bidbox/demo/`: 1440x1700
   - `/bidbox/contact/`: 1440x1700
   - `/404.html`: 1440x1700
4. `browsingContext.setViewport` 로 뷰포트를 설정하고 `browsingContext.navigate` 로 페이지 이동 후 `load` 완료 시점부터 1500ms 를 대기했습니다.
5. `scripts/audit/render.swift` 의 `probe` 와 동일한 방식으로 `script.evaluate` 를 통해 다음 항목들을 측정했습니다.
   - `document.body` 의 배경색(`backgroundColor`)과 텍스트색(`color`)
   - sRGB 상대 휘도 선형화(0.03928 이하면 `x/12.92`, 초과면 `((x+0.055)/1.055)^2.4`, 휘도 `0.2126R + 0.7152G + 0.0722B`)를 통한 명도 대비 (큰 휘도 + 0.05) / (작은 휘도 + 0.05) 계산 (소수 둘째 자리 반올림)
   - 데스크톱 내비 CTA 높이(`header nav a.btn-primary` 의 `getBoundingClientRect().height` 반올림)
   - 허브 카드 paddingTop(`main a.card` 의 `getComputedStyle().paddingTop`, 요소 없으면 `null`)
   - 요금 행 개수(`#plans li.card` 개수)
   - 요금 다이얼로그 존재 여부(`dialog` 요소 존재 불리언)
6. 콘솔 오류 및 경고 건수는 BiDi 의 `log.entryAdded` 이벤트로 페이지별로 수집했습니다.
7. 동일한 측정을 두 번 실행하여 원시 JSON 을 `/tmp/narani-firefox-metrics-20260927/run1.json` 과 `/tmp/narani-firefox-metrics-20260927/run2.json` 에 각각 저장했습니다. 두 파일 모두 측정 시각(`measuredAt`)을 포함하며 두 번째 실행이 첫 번째 파일을 덮어쓰지 않았습니다.
8. 측정 완료 후 Firefox 와 Python HTTP 서버 프로세스를 모두 종료했습니다. 포트 8921 과 9921 에 잔여 리스너가 없음을 확인했습니다. 스크립트와 임시 프로필, JSON 파일은 저장소에 넣지 않고 `/tmp/narani-firefox-metrics-20260927/` 에만 유지했습니다.

## 해석

- WebKit 기준선([`../context/CURRENT_STATE.md`](../context/CURRENT_STATE.md) 3장)과 비교했을 때 본문 배경색, 텍스트색, 명도 대비, JS 오류 건수, 그리고 데스크톱 내비 CTA 높이(44px), 허브 카드 paddingTop(`null`), `#plans li.card` 개수(0), 요금 다이얼로그 존재 여부(`true`)가 전 항목에서 완전히 일치합니다.
- Chrome 대비 측정 보고서([`크롬_대비_20260927.md`](크롬_대비_20260927.md))와 비교했을 때에도 본문 배경색, 텍스트색, 명도 대비(라이트 15.88, 다크 19.46), 콘솔 오류 및 경고 건수(0건)가 동일합니다.
- Chrome 치수 측정 보고서([`크롬_치수_20260927.md`](크롬_치수_20260927.md))와 비교했을 때에도 데스크톱 내비 CTA 높이, 허브 카드 paddingTop, 요금 행 개수, 요금 다이얼로그 존재 여부 등 4개 치수 항목이 모두 동일합니다.
- 두 번의 독립 실행에서 측정값이 오차 없이 재현되었으므로 로딩 지연에 따른 변동 없이 안정적인 결과로 평가됩니다.
- 본문 텍스트 명도 대비는 라이트 15.88:1, 다크 19.46:1 로 WCAG 기준 4.5:1 을 크게 상회합니다.
- CTA 버튼 높이 44px 는 Tailwind CSS 4 의 important 접미사(`min-h-[44px]!`)가 Firefox 에서도 의도대로 해석되어 최소 터치/클릭 규격을 충족함을 확인해 줍니다.

## 한계

- 본 측정값은 macOS 환경에서 `--headless` 모드의 Mozilla Firefox 156.0.1 로 얻은 결과이며, 일반 창(GUI) 환경의 Firefox 렌더링 결과와 완전히 동일하다고 단정할 수 없습니다.
- 측정 대상은 `document.body` 의 computed 스타일 배경 및 텍스트 색상과 명시된 probe 선택자이므로, 페이지 내 세부 섹션이나 이미지 상단 텍스트 등의 대비까지 대표하지는 않습니다.
- 측정은 빌드 커밋 `ee2790e9a0adc4d1d5828e8b1c56b68e6852d92d` 의 dist 복사본을 대상으로 하였으므로, 향후 소스 코드 수정 후 새로 빌드할 경우 결과가 달라질 수 있습니다.
- 페이지 로드 이벤트 후 1500ms 를 대기하였으나 웹 폰트 동적 로딩이나 네트워크 환경에 따라 다른 환경에서는 타이밍 차이가 발생할 수 있습니다.
