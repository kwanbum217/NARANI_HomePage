## 3. 리뷰어의 "문장째 복사" 판정은 정확하지 않았습니다

리뷰서 1절은 faq.ts 의 2번·3번 항목이 `POINT_NOTE` 와 요금 사용 문장을
"문장째 복사"했다고 적었습니다. 문자 단위로 비교한 결과 **복사가 아니라 변형**입니다.

| 비교 | 차이 |
| --- | --- |
| `faq.ts` 2번 vs `pricing.astro:79` | 가운뎃점 **앞 공백 없음** vs **양옆 공백** (30자 / 32자) |
| `faq.ts` 3번 vs `POINT_NOTE` | `네.` 접두어 + `사용되며` vs `사용됩니다` (43자 / 41자) |

두 비교 모두 완전히 동일한 부분 문자열이 아니었습니다. 이 차이를 명세에
적지 않으면 워커는 존재하지 않는 "중복"을 hunt합니다. 코디네이터가 먼저
측정해서 명세에 실측값으로 넣었습니다.

## 4. 코디네이터가 직접 재현한 음성 검증

워커 자기보고를 그대로 믿지 않고 재현했습니다.

| 되돌린 것 | 기대 | 실제 |
| --- | --- | --- |
| `applicationCategory` → `'SoftwareApplication'` | 구조화 데이터 검사 exit 1 | exit 1, "5건" |
| `pricing.astro:193` → "프로그램 접속" | 카피 검사 exit 1 | exit 1, "1건" |
| `{POINT_USAGE_RULE}` → 하드코딩 문자열 | 카피 검사 exit 1 | **exit 0 — 검사 없었음** |

**세 번째가 처음엔 실패했습니다.** W5 는 명세에 적힌 대로 `POINT_NOTE` 반복만
검사했고 `POINT_USAGE_RULE` 은 검사하지 않았습니다. 명세를 지킨 결과였습니다.
다만 그 지점이 바로 코디네이터가 배선한 곳이라 방어 가치가 있습니다. 제가
`check-copy-consistency.mjs` 에 검사를 추가하고 다시 재현해 exit 1 을 확인했습니다.

**코디네이터가 명세를 빠뜨린 것입니다.** 워커의 결함이 아닙니다.

## 5. 폰트 서브셋 검사 문자 352 → 350

`sans-serif` 글자 수가 2 줄었습니다. 집합을 직접 비교해 확인했습니다.

- 사라진 문자: **`램속`** 정확히 2자

이는 "프로그램 접속"이 페이지에서 사라진 결과입니다. 의도한 회귀이며,
이전 세션과 같은 유형(문자 수 변화 → 집합 비교 → 사라진 문자 확인)입니다.

주의: 게이트가 세는 값(350)과 이 비교값(353 vs 355)은 개행 처리 방식이 달라
2 차이가 납니다. **방향은 같습니다.**
